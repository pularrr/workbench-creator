# P2 阶段文档 · v0.7–v0.8 持久化与智能体可视化

> 阶段目标：将存储层从单文件 JSON 升级为 SQLite 以支撑多会话并发，在工作台中实现 AgentRun 实时状态可视化，并增强参考文档结构提取与图表描述能力。
> 预计版本：v0.7.0（SQLite + AgentRun 可视化）→ v0.8.0（参考结构提取 + 图表描述）
> 状态：规划中

| 编号 | 目标 | 验收指标 |

## 二、需求拆解

### 2.1 G1 · SQLite 持久化

**现状**：`domain-store.js` 用单个 `state.json`（当前 1.3MB+），每次写操作全量 `JSON.stringify` + `fs.writeFile`，无并发控制，多会话同时写会互相覆盖。

**需求**：
1. 新增 `src/storage-sqlite.js`，定义 `StorageBackend` 接口：
   ```js
   interface StorageBackend {
     init(): Promise<void>
     getState(): Promise<State>
     saveState(state: State): Promise<void>
     getProject(projectId): Promise<Project|null>
     upsertProject(project: Project): Promise<void>
     listProjects(): Promise<ProjectSummary[]>
     close(): Promise<void>
   }
   ```
2. 用 `better-sqlite3`（同步 API，性能好）实现。表设计：
   - `projects(id, name, title, degree_type, target_words, status, planning_revision, manuscript_revision, template_revision, updated_at, data BLOB)`
   - `session_bindings(session_id, project_id, created_at)`
   - `meta(key, value)`（schema_version 等）
   - `data` 列存项目完整 JSON（BLOB），避免为每个嵌套字段建表；查询用生成列或 FTS5。
3. 迁移：首次启动时若存在 `state.json`，自动导入到 SQLite，备份原文件为 `state.json.bak`。
4. `domain-store.js` 改为依赖 `StorageBackend` 接口，默认用 SQLite；保留 JSON 后端作为 fallback（环境变量 `THESIS_STORAGE=json`）。
5. 并发控制：SQLite WAL 模式 + 写事务，`better-sqlite3` 本身线程安全。
6. 全量备份 API：`thesis_export_state` 导出 SQLite 为 JSON（兼容旧格式）。

**性能指标**：
- 100 项目、1000 分块规模：`getWorkbench` < 50ms，`saveState` < 20ms。
- 启动（init + 建表）< 500ms。

### 2.2 G2 · AgentRun 可视化

**现状**：`agent-run.js` 有完整状态机（13 个状态），但工作台只能看到 `agentRuns` 列表的 JSON，无可视化。

**需求**：
1. `workbench-server.js` 新增 API：
   - `GET /api/agent-runs`：列出当前项目所有 run（摘要）
   - `GET /api/agent-runs/:id`：单个 run 详情（含 steps 时间线、observations、artifacts、预算）
   - `GET /api/agent-runs/:id/steps`：步骤流（SSE 可选，v0.8 后）
2. 工作台前端新增"任务"tab：
   - 左侧：run 列表（状态色标 + taskType + 进度条）
   - 右侧：选中 run 的状态机图（13 状态节点 + 当前高亮 + 已走路径）
   - 下方：步骤时间线（from→event→to，耗时，summary）
   - 预算面板：usedSteps/maxSteps、retrievalAttempts、revisionAttempts
3. 状态机图用 SVG 绘制，节点位置固定（分层布局），当前状态脉冲动画。
4. 操作按钮：暂停/恢复/取消（调用对应工具 API）。

### 2.3 G3 · 参考文档结构提取

**现状**：`literature` 条目需手动填写 title/authors/abstract/year，导入文档时不自动提取。

**需求**：
1. 新增 `src/reference-extractor.js`：
   - `extractMetadata(text, filePath) → {title, authors, year, abstract, keywords, venue, doi}`
   - 策略：正则（标题行、作者行、摘要段、年份）+ 启发式（首页前 2000 字符优先）
   - PDF 优先用 officeparser 的 `ast.metadata`（title/author/creator）
2. `importSourceFile` / `importSourceText` 增加 `extractReferences: true` 选项，自动创建 literature 条目。
3. 提取结果置信度标注（high/medium/low），low 时提示用户核对。

### 2.4 G4 · 图表多模态描述

**现状**：文档中的图片/图表被忽略，分块只有文字。

**需求**：
1. `document-parser` 增加 `extractImages: true` 选项，提取文档中的图片（officeparser 的 `extractAttachments`）。
2. 新增 `src/figure-describer.js`，provider 抽象：
   - `multimodal-llm`：调用支持视觉的 LLM（GPT-4V / Claude 3 / 豆包视觉）生成描述
   - `ocr-caption`：本地 OCR + 图注文字拼接（兜底，无需外部依赖）
3. 图片描述绑定到对应分块的 `figures` 字段：`[{id, page, caption, description}]`。
4. 检索时图片描述参与 embedding（`figure.description` 拼入分块文本）。

## 三、技术方案与架构

### 3.1 SQLite 表设计

```sql
PRAGMA journal_mode=WAL;
CREATE TABLE projects (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  title TEXT,
  degree_type TEXT,
  status TEXT,
  planning_revision INTEGER DEFAULT 0,
  manuscript_revision INTEGER DEFAULT 0,
  template_revision INTEGER DEFAULT 0,
  updated_at TEXT,
  data BLOB NOT NULL
);
CREATE TABLE session_bindings (
  session_id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  created_at TEXT,
  FOREIGN KEY (project_id) REFERENCES projects(id)
);
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);
CREATE INDEX idx_projects_updated ON projects(updated_at DESC);
```

### 3.2 AgentRun 状态机布局

13 状态分 5 层：
- L1: created → planning
- L2: awaiting_plan_confirmation → (retrieving ↔ evaluating_evidence)
- L3: drafting → validating
- L4: reviewing → awaiting_user_decision
- L5: applying → completed
- 终止态: cancelled / failed / budget_exceeded / needs_user_material

SVG 节点 80×40，层间距 120，状态间箭头。

## 五、风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| `better-sqlite3` 原生模块在 Windows 编译失败 | SQLite 后端不可用 | 预编译二进制（`better-sqlite3` 官方提供）；保留 JSON fallback；CI 覆盖 Windows |
| state.json → SQLite 迁移数据丢失 | 历史项目丢失 | 迁移前自动备份 `state.json.bak`；迁移后校验项目数/分块数一致；不一致时回滚 |
| AgentRun 前端 SVG 复杂度高 | 工作台加载慢 | 状态机图静态 SVG（非动画库）；步骤时间线虚拟滚动（>100 步时折叠） |
| 参考提取正则误判 | literature 条目错误 | 置信度标注 + 用户确认；不自动覆盖已有条目 |
| 多模态 LLM API 成本 | 图表描述费用高 | 默认 ocr-caption 兜底；multimodal-llm 需显式开启 + 预算上限 |
