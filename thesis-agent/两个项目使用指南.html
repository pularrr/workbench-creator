thesis-agent v1.2.0workbench-core v0.1.0 证据驱动的论文写作智能体工作台 → 可插拔文本处理工作台框架（v2.0 演进）

0 · 先看懂关系

thesis-agent 是把「AI 只能提案 → 系统必须审批 → 证据必须追踪 → 修改必须版本化」落到工程架构里的论文专用多 Agent 应用； workbench-core 把它的核心架构（状态机 / 存储 / 双区工作台 UI / 模板 / 版本）抽象成通用框架， 通过 Framework / Logic / Evidence（+可选 Material）三层插件支持论文、专利、合同、技术报告等任务，并可用 LLM 一键生成新任务类型的插件包。

thesis-agent（论文专用）→ 抽象核心架构 → workbench-core（通用框架）→ 内置 thesis 插件patent 插件+ 可生成 contract / tech-report / generic
当前机器环境核对（已实测）： Node v22.23.2 ✅（满足 ^22.19.0 要求）· npm 10.9.8 ✅ · dsh CLI 已安装 ✅ · 两个项目 node_modules 均已安装 ✅ · 当前仅 dsh-thesis-agent 已注册到 web profile， workbench-core 尚未注册（要用它需先执行注册）。

1 · 项目一：thesis-agent（论文写作工作台）

1.1 安装与启动

# 在 D:\雷达毕设相关\high_star\thesis-agent 目录下
dsh plugin --profile web add .     # ① 注册插件（当前已注册，可跳过）
npm run setup                       # ② 安装 Preset 行为资产（写作/审查 Agent 配置）
dsh web                             # ③ 启动 DSH（含工作台服务）

启动后访问：论文写作工作台 http://127.0.0.1:3199；DSH 对话界面会话头部会出现「论文工作台」按钮。 改过代码后需重装：dsh plugin --profile web remove dsh-thesis-agent → dsh plugin --profile web add . → npm run setup。

1.2 典型使用路径（对话驱动）

建项目→定规划（大纲+行文逻辑，需确认）→ 导材料（扫描目录→分块→建索引）→生成章节（先候选后确认）→ 审查（只读建议）→修订批次→导出 Word / PDF 
用户：创建一篇目标 30000 字的硕士论文项目，题目为"面向论文写作的混合检索方法研究"。
      我暂时没有参考论文，请先生成默认大纲与行文逻辑，不要生成正文。
用户：生成系统设计章节。          ← 系统先提交生成范围候选，你确认后才落笔
用户：请扫描目录 D:\我的论文资料 并将论文导入为参考材料。   ← 开启证据约束
用户：用 SiliconFlow 的 bge-m3 向量模型，Key 是 sk-xxx    ← 配置真实 Embedding（可选）
用户：让审查 Agent 看看，然后导出 Word 和 PDF

无证据处会写入 [待补充证据] 占位，禁止捏造数字与文献；正文按段落块保存，支持命名快照 / 块级 diff / 恢复。

2 · 项目二：workbench-core（可插拔工作台框架）

2.1 安装与启动

# 在 D:\雷达毕设相关\high_star\workbench-core 目录下
npm install                          # ① 装依赖（已装可跳过）
dsh plugin --profile web add .       # ② 注册插件
# ③ 重启 DSH（重要：注册后需重启才生效）

启动后通过 DSH 对话使用，工作台 UI 同样在 http://127.0.0.1:3199（由 wb_open_workbench 打开）。

2.2 典型使用路径（对话驱动）

用户：打开工作台
DSH：wb_open_workbench → http://127.0.0.1:3199

用户：创建一个论文项目，关于毫米波雷达水分检测
DSH：wb_create_project({ name: "毫米波雷达水分检测", taskType: "thesis" })

用户：创建一个专利项目，关于一种新的检测装置
DSH：wb_create_project({ name: "新型检测装置", taskType: "patent" })

核心亮点：生成新任务类型插件包

用户：基于论文工作台架构，帮我生成一个面向法律合同审查的工作台
DSH：wb_analyze_task_description({ description: "法律合同审查" }) → detectedType: "contract"
DSH：wb_generate_plugin_bundle({ taskType: "contract", name: "Contract Workbench" })
     → 生成 ./generated-plugins/contract-workbench/

生成器只会在 generated-plugins/<taskType>-workbench/ 创建新包，不会改 workbench-core 源码； 每个包含 plugin-spec.json（领域唯一配置来源）、plugin.manifest.json、读取 spec 的 src/index.js、安装前静态校验脚本 scripts/verify.mjs。 生成后自动执行静态验证，也可 wb_verify_generated_plugin_bundle 复查；通过后再按包内 README 安装。 工作台右侧「规格」页提供 Spec Studio：新建草案 → 编辑 JSON → 校验 → 生成隔离插件包。

4 · 注意事项（重要）

① 端口冲突：两个项目的工作台默认都监听 127.0.0.1:3199，同时注册并启用会端口冲突（EADDRINUSE）。 建议同一时间只启用一个插件；若必须并存，可改端口（两个项目均支持 options.port 参数，如改为 3200）。
② 注册互斥与重启：两个插件都注册到同一个 --profile web。切换使用时： 在目标项目目录执行 dsh plugin --profile web add .（必要时先 remove 另一个），然后重启 DSH。
③ 数据目录：thesis-agent 数据默认持久化在 ~/.dsh/storages/thesis-agent/state.json（可切 SQLite）； 删除 / 重装插件前如需保留论文进度，先备份该文件。
④ API Key 不落盘：Embedding Key 仅存进程内存，DSH 重启后需重新填写，可用 apiKeyEnv 指向环境变量规避。
⑤ 最快上手建议：写论文用 thesis-agent（证据约束 + 导出保真更适合毕设场景）； workbench-core 适合「探索框架能力 / 同时要专利或合同写作」时切换体验，或用它自研新任务类型。
