# P3 阶段文档 · v1.0+ 深度集成与可插拔架构

> 阶段目标：将论文工作台从独立网页深度嵌入 DSH 会话区域，对接 RAGFlow 企业级检索，实现图表自动编号与交叉引用，并将模板体系升级为可插拔 Profile 架构，达到 v1.0 生产可用。
> 预计版本：v0.9.0（DSH 内嵌 UI）→ v1.0.0（RAGFlow + 图表交叉引用 + Profile 架构）
> 状态：规划中

---

## 一、阶段目标与范围

### 1.1 目标

| 编号 | 目标 | 验收指标 |
|---|---|---|
| G1 | 论文工作台深度嵌入 DSH 会话区域，不再依赖独立 3199 网页 | DSH 会话右侧/底部可直接渲染工作台面板，大纲/正文/审核/任务四 tab 可用 |
| G2 | 对接 RAGFlow Core（PostgreSQL + Qdrant + Redis），支撑万级文献企业级检索 | 10000 分块规模检索 P99 < 200ms；混合检索 + rerank 全链路 |
| G3 | 图表自动编号与交叉引用导出 | 正文中 `[图1]`/`[表2]` 自动编号，插入/删除图表后全文引用自动更新，导出 docx/latex 正确 |
| G4 | 模板 Profile 可插拔架构 | 模板/字体/引用格式/导出规则封装为 Profile，可热切换、可分发、可版本化 |

### 1.2 范围

**In scope**：
- DSH client UI 深度集成（右侧面板 + 会话内卡片）
- RAGFlow Core Adapter（检索/分块/embedding/rerank 全链路）
- 图表编号与交叉引用引擎
- Template Profile 架构与 Profile 市场雏形
- v1.0 发布工程（版本冻结、文档、迁移指南）

**Out scope**（v1.0 后）：
- 多用户协同编辑
- 实时多人评论
- 云端同步/多设备
- 插件市场商业化

## 二、需求拆解

### 2.1 G1 · DSH 会话深度集成

**现状**：工作台是独立 3199 网页，DSH 会话内只有一个"论文工作台"按钮（`client.js`），点击开新窗口。用户期望"进入预设就出现工作台"。

**需求**：
1. `client.js` 升级为完整 DSH client 插件，注入：
   - **右侧面板**（`conversation.session.panel` slot）：默认折叠，点击展开后渲染工作台四 tab（大纲/正文/审核/任务）
   - **会话内卡片**：工具调用 `thesis_get_workbench` 后自动渲染为可交互卡片（而非纯 JSON）
   - **快捷操作栏**：会话输入框上方增加"新建项目/导入材料/生成大纲/导出"快捷按钮
2. 面板与 3199 网页共享同一套前端组件（抽离 `client/workbench/` 为共享模块）。
3. 面板通过 DSH client 的 `tools.call` 直接调用 thesis 工具，不再依赖 HTTP 3199（3199 保留为独立模式 fallback）。
4. 预设 `thesis-writer-v0` 升级为 v1，默认开启右侧面板。
5. 面板状态持久化（展开/折叠、当前 tab）到 DSH client localStorage。

**DSH client 注入点**：
```
conversation.session.panel          → 右侧工作台面板
conversation.session.header.utilities → 头部按钮（保留）
conversation.message.tool_result    → 工具结果卡片渲染
conversation.composer.actions       → 输入框快捷操作
```

### 2.2 G2 · RAGFlow Core Adapter

**现状**：检索是本地 `hybridSearch`（BM25 + local-hash embedding），适合百级分块；万级文献需要企业级向量检索。

**需求**：
1. 新增 `src/ragflow-adapter.js`，定义 `RetrievalBackend` 接口：
   ```js
   interface RetrievalBackend {
     init(): Promise<void>
     indexChunks(projectId, chunks): Promise<void>
     search(projectId, query, options): Promise<Chunk[]>
     deleteProject(projectId): Promise<void>
     status(): Promise<{indexedChunks, totalChunks, backend}>
   }
   ```
2. RAGFlow Core 部署架构：
   - PostgreSQL：元数据（项目/文档/分块/引用）
   - Qdrant：向量存储（embedding 维度可配）
   - Redis：缓存 + 检索结果去重 + 分布式锁
   - DeepDoc：文档解析（表格 TSR / OCR / 版面分析）
3. Adapter 实现：
   - 分块：复用现有 `chunkText`，或调用 RAGFlow DeepDoc 分块
   - Embedding：复用现有 `embedding-provider.js`（local-hash / openai-compatible）
   - 检索：Qdrant 向量检索 + PostgreSQL 全文检索（tsvector）混合
   - Rerank：复用 P1 `reranker.js`
4. 配置：`THESIS_RETRIEVAL_BACKEND=local|ragflow`，默认 local；ragflow 模式需配置 `RAGFLOW_PG_URL`、`RAGFLOW_QDRANT_URL`、`RAGFLOW_REDIS_URL`。
5. 迁移工具：`thesis_migrate_retrieval_backend`（local → ragflow，全量重建索引）。
6. Docker Compose 一键部署 RAGFlow Core（`deploy/ragflow/docker-compose.yml`）。

**性能指标**：
- 10000 分块：检索 P99 < 200ms（Qdrant + 缓存）
- 索引 1000 分块：< 30s（批量写入）
- 检索结果一致性：local 与 ragflow 同一查询 top-5 重合率 ≥ 70%

### 2.3 G3 · 图表自动编号与交叉引用

**现状**：正文块是纯 Markdown，图表无编号，引用靠手动写"如图1所示"，插入图表后编号全乱。

**需求**：
1. 新增 `src/citation-engine.js`：
   - 扫描正文块，识别图/表/公式占位符：`![caption](figure:id)`、`[表 caption](table:id)`、`$...$`（公式）
   - 按出现顺序自动编号：图1、图2... / 表1、表2... / 公式(1)、(2)...
   - 识别引用标记：`[图1]`、`[表2]`、`[公式(3)]`，自动关联到对应编号
   - 插入/删除图表后，全文编号与引用自动重排
2. 正文块增加 `figures`、`tables`、`equations` 字段（结构化元数据）。
3. 导出：
   - docx：图表编号 + 题注 + 交叉引用域（Word 可更新）
   - latex：`\label{fig:id}` + `\ref{fig:id}` + `\caption`
   - html：`<figure>` + `<figcaption>` + `<a href="#fig:id">`
4. 工作台"正文"tab 增加图表面板：列出所有图表，点击定位到正文位置。
5. 引用冲突检测：引用了不存在的图表编号时高亮警告。

### 2.4 G4 · Template Profile 可插拔架构

**现状**：模板（`master-template.js`）、字体、引用格式（`reference-templates`）、导出规则分散在代码中，无法热切换。

**需求**：
1. Profile 定义（JSON Schema）：
   ```json
   {
     "id": "xjtu-master-2024",
     "name": "西安交通大学硕士论文 2024",
     "version": "1.0.0",
     "template": { "sections": [...] },
     "fonts": { "body": "宋体", "heading": "黑体", "code": "Consolas", "baseSize": 12 },
     "citationStyle": "gb-t-7714-2015",
     "export": { "docx": {...}, "latex": {...}, "page": { "size": "A4", "margin": {...} } },
     "metadata": { "institution": "西安交通大学", "degree": "master", "year": 2024 }
   }
   ```
2. Profile 加载机制：
   - 内置 Profile（`assets/profiles/`）：generic-master、generic-bachelor、ieee-conference
   - 用户 Profile（`~/.dsh/thesis/profiles/`）：可放自定义 JSON
   - 项目 Profile：项目内 `.thesis/profile.json`，优先级最高
3. Profile 热切换：`thesis_apply_profile {profileId}`，切换后大纲/字体/引用/导出规则即时生效（需重新生成大纲时确认）。
4. Profile 版本化：Profile JSON 带 `version`，升级时自动迁移；不兼容时提示。
5. Profile 市场雏形：`thesis_search_profiles`（从内置 + 用户目录搜索）、`thesis_export_profile`（导出为可分发 JSON）。
6. P1 的模板包机制升级为 Profile 的子集（`template` 字段），向后兼容。

## 三、技术方案与架构

### 3.1 v1.0 整体架构

```
┌─────────────────────────────────────────────────┐
│              DSH Client (Web)                     │
│  ┌──────────┐  ┌──────────────────────────────┐ │
│  │ 会话区    │  │ 右侧工作台面板 (P3 新增)      │ │
│  │          │  │ 大纲|正文|审核|任务            │ │
│  │ 工具卡片  │  └──────────────────────────────┘ │
│  └──────────┘         │ tools.call               │
└───────────────────────┼──────────────────────────┘
                        ▼
┌─────────────────────────────────────────────────┐
│           dsh-thesis-agent (Node)                │
│  index.js (tools) ← domain-store.js              │
│       ↓                    ↓                      │
│  lossless.js        StorageBackend               │
│       ↓               ↙        ↘                 │
│  reranker.js   storage-sqlite  storage-json     │
│       ↓                    ↓                      │
│  RetrievalBackend ← ragflow-adapter (P3)        │
│       ↓                    ↓                      │
│  citation-engine.js  template-profile.js (P3)    │
└─────────────────────────────────────────────────┘
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
      PostgreSQL      Qdrant        Redis
      (元数据)       (向量)        (缓存/锁)
```

### 3.2 DSH 内嵌 UI 技术要点

- 共享前端组件库：抽离 `client/workbench/`（React 组件），3199 网页和 DSH 面板共用。
- DSH panel 通过 `ctx.slots.inject('conversation.session.panel', ...)` 注入。
- 工具结果卡片：监听 `conversation.message.tool_result` 事件，匹配 `thesis_*` 工具，渲染为对应卡片。
- 状态管理：用 DSH client 的 `useSessionStorage` + 本地状态，不引入额外状态库。

### 3.3 RAGFlow Adapter 数据模型

```sql
-- PostgreSQL
CREATE TABLE documents (id, project_id, name, source_key, content_hash, metadata jsonb, created_at);
CREATE TABLE chunks (id, document_id, project_id, chunk_index, content, start_line, end_line, embedding_id, metadata jsonb);
CREATE TABLE citations (id, project_id, chunk_id, reference_key, context, created_at);
CREATE INDEX ON chunks USING gin (to_tsvector('simple', content));

-- Qdrant
collection: thesis_chunks_{projectId}
  vector: 192 (local-hash) 或 1536 (openai)
  payload: {chunkId, documentId, projectId, sourceName, chunkIndex}
```

## 五、风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| DSH client slot API 变更或不支持 panel 注入 | 内嵌 UI 无法实现 | 提前与 DSH 版本对齐；保留 3199 独立模式作为 fallback；panel 注入失败时降级为头部按钮 |
| RAGFlow 部署复杂度高（PG+Qdrant+Redis） | 用户难以启用 | Docker Compose 一键部署；默认 local 后端；详细部署文档；健康检查脚本 |
| 图表交叉引用与现有正文块格式不兼容 | 历史项目正文需迁移 | citation-engine 兼容纯 Markdown（无编号时不报错）；迁移工具自动扫描并添加编号 |
| Profile 热切换导致大纲/正文不一致 | 切换后格式混乱 | 切换时提示"需重新生成大纲"；只切换未锁定的部分；锁定的章节保留原格式 |
| v1.0 范围蔓延 | 延期 | 严格按 M5/M6 切分；M5 先发布内嵌 UI（可独立用），M6 再发 RAGFlow+图表+Profile |
