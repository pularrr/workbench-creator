# readme_2 · thesis-agent（证据驱动的论文写作智能体工作台）

> **一句话定位**：一个把「AI 只能提案 → 系统必须审批 → 证据必须追踪 → 修改必须版本化」落到真实工程架构里的多 Agent 应用，面向毕业论文写作场景，从架构层面治理大模型最核心的两个问题——**幻觉**与**不可控**。它是 LLM Agent 应用工程的范本，完整走通「多 Agent 编排 → 工具治理 → RAG 检索 → 受控生成 → 人机审批 → 多格式导出」全链路。

---

## 1. 项目能做什么 & 为什么做这个项目

**能做什么**
- 把写论文拆成一条受控流水线：`建项目 → 定规划 → 导材料 → 生成 → 审查 → 修订 → 版本 → 导出`。
- 在对话里用自然语言驱动，配套一个双区（正文 / 大纲·行文逻辑·来源·版本·任务·模板·设置）Web 工作台（`:3199`）。
- 生成的内容「有据可依」：缺证据处写 `[待补充证据]`，禁止捏造数字与文献；引用支持 GB/T 7714 与 APA；可导出 DOCX 与（XeLaTeX 编译的）PDF。

**为什么做**
通用 LLM 写作应用有三个被反复诟病的硬伤：
1. **幻觉**：随意编造文献、捏造数据、虚构引用，学术场景不可接受；
2. **不可控**：AI 一键「生成全文」，覆盖用户已写内容、不按用户确认的规划走；
3. **不可追溯**：说不清「为什么这么写、依据是什么、改了哪一版」。

本项目不做一个「聊天生成整篇论文」的 Demo，而是把它当作**生产级 Agent 系统**来设计：用领域状态机约束流程、用证据检索闭环约束内容、用双 Agent 权限隔离约束权力、用版本事务与乐观并发约束数据。适用岗位画像：AI 应用开发 / LLM Agent 应用 / RAG 工程 / 智能写作产品。

## 2. 怎么使用这个项目

**环境**：Node.js `^22.19.0 || >=24.0.0` + DeepSeek Harness（DSH）；可选 XeLaTeX 用于 PDF 编译。

```powershell
dsh plugin --profile web add .   # 注册插件
npm run setup                     # 安装 Preset 行为资产
dsh web                           # 启动 DSH（含工作台）
```
启动后访问论文工作台 http://127.0.0.1:3199 。

**典型使用路径**
1. 对话：「创建 3 万字硕士论文项目《面向论文写作的混合检索方法研究》」→ 系统先给大纲与行文逻辑，等你确认；
2. 「扫描 D:\refs 导入参考资料」→ 解析/分块/建向量索引，开启证据约束；
3. 「生成系统设计章节」→ 系统**先提交生成范围候选**，你确认后才落笔；
4. 让审查 Agent 提建议（只读，只提交建议不改正文），逐条接受/拒绝 → 修订批次 → Patch 二次审批；
5. 导出 Word 与 PDF。
（API Key 仅存进程内存，可用 `apiKeyEnv` 指向环境变量；XeLaTeX 路径用 `THESIS_XELATEX_PATH` 指定。）

## 3. 项目最终获得的效果

- **可运行的生产级系统**：覆盖一条真实论文写作工程链路，而非一次性脚本。
- **架构层治理幻觉与不可控**：证据约束生成 + 双 Agent 最小权限隔离 + 受控状态机 + 版本事务，使「AI 失控」变成可观测、可干预、可审计的工程问题。
- **量化完成度**：165 项自动化测试 pass / 0 fail / 3 skip（XeLaTeX 环境依赖），两个桥接回归脚本，`npm audit` 0 漏洞。
- **可移植核心**：`src/` 纯领域逻辑 + Node 标准库，完全不依赖 DSH 运行时，可独立测试、复用到其他宿主（这也是 `test/` 能直接 `node --test` 跑通的原因）。

## 4. 项目亮点（如何处理工程问题）

| # | 亮点 | 工程价值 / 解决的问题 |
|---|---|---|
| 1 | **证据约束生成** | 无检索证据禁止落笔，缺失写 `[待补充证据]`，从架构层面治理幻觉而非提示词补救 |
| 2 | **双 Agent 权限隔离** | 写作/审查 Agent 用独立工具白名单，审查 Agent 仅 4 个只读工具，写入工具在注册层就不可见——多 Agent 最小权限可复现范例 |
| 3 | **受控 AgentRun 状态机** | 11 状态、显式事件转移表、预算上限、完整审计轨迹、暂停/恢复/取消；`recommendedNextEvent` 机制消除 LLM「猜事件名」导致的失控 |
| 4 | **可插拔 RAG 全链路** | Embedding 6 厂商预设、Rerank 3 提供商自动降级、RAGFlow Adapter、JSON/SQLite 双存储，每个外部依赖都是抽象接口，切换成本≈0 |
| 5 | **乐观并发 + 无损序列化桥** | 写操作带 `expectedRevision` 冲突检测；工具返回值经 Lossless-JSON 守卫清洗（剔除 NaN/循环引用等），保证工具桥无损往返 |
| 6 | **块级版本事务** | 正文按段落块存储，命名快照/块级 diff/无损恢复，用户锁定块永不覆盖，接近数据库事务思维 |
| 7 | **对话 ↔ 工作台双向闭环** | Web 工作台（:3199）与 DSH 对话通过「重新生成请求队列」联动，自然语言驱动 + 可视化精细编辑 |
| 8 | **导出保真** | DOCX 公式上标/下标渲染、LaTeX 数学符号映射、GB/T 7714 / APA 引用、XeLaTeX 编译 PDF，追求排版正确而非「能导出」 |

## 5. 技术路线（AI + 前后端开发视角）

**AI 层（概率性内核）**
- **多 Agent 编排**：写作 Agent（9 个领域 Skill）+ 审查 Agent（只读），写审分离。
- **工具治理（工具桥）**：65 个 `thesis_*` 工具统一注册，JSON Schema 强校验、Lossless-JSON 序列化守卫、`expectedRevision` 乐观并发、工具级并发安全标记、writer/review 白名单分流。
- **RAG 检索**：多格式解析（officeparser + pdfjs-dist）→ 结构分块 → Embedding（local-hash 192 维零依赖 / OpenAI-compatible 6 家预设）→ 混合检索（`0.45×关键词 + 0.55×向量`）→ 可选 Rerank（本地 BM25+Bigram / Cohere / Voyage 自动降级）→ 预算化证据包 → 来源绑定。
- **受控生成 / 人机协作**：范围候选 → 用户确认 → 候选稿（不改正文）→ 接受/拒绝 → 修订批次 → Patch 二次审批。

**后端 / 领域引擎层（确定性外壳）**
- Node.js ESM，全项目运行；DeepSeek Harness（DSH）Bundle 机制做 Agent 预设、工具注册、Skill 文件系统、会话绑定。
- 领域状态聚合（项目/规划/正文/版本/建议）、AgentRun 状态机（事件表/预算/暂停恢复/模式预设）、存储抽象（JSON 默认 / SQLite WAL 可选，schemaVersion 只增不减 + 迁移）。
- 安全：API Key 内存暂存、目录扫描需显式 `approved`、Embedding endpoint 协议校验、`-no-shell-escape` 编译。

**前端层**
- 原生 HTML/CSS/JS（零框架）内嵌 `node:http` 服务，双区 4:3 可拖拽工作台；通过 REST API 与 `src/domain-store` 交互。
- 对话侧 `client.js` 侧边面板自动跟随项目、打开工作台，实现自然语言 ↔ 可视化编辑双向联动。

**工程化**
- 测试：`node --test` 165 项 + 两个桥接回归脚本；`npm audit` 0 漏洞；P0–P3 分阶段文档与验收标准（工具桥无损、乐观并发、schemaVersion 迁移、测试门槛全绿、文档同步）。

> 设计取向：**核心能力自研、外部依赖走抽象接口**——检索/Rerank/Embedding/存储/OCR 全部 Provider 抽象层，可插拔、可降级、可替换，这是 AI 应用「不被单一厂商锁死」的关键设计。
