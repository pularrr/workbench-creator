# 开发报告

## 2026-09-13：交互协作与统一 Diff 改造完成

- Core 增加统一、版本化 ChangeSet，覆盖大纲、行文逻辑、正文、审查意见四类 Diff；写入前保持 `awaiting_confirmation`，按 `baseRevision` 防止过期变更覆盖新内容。
- 增加 DSH 工具 `wb_create_change_set`、`wb_get_change_set`、`wb_apply_change_set`，以及对应 HTTP API；只应用用户勾选项，空选择表示拒绝。
- 再生成候选自动关联正文 ChangeSet，工作台统一审查区同时展示四类差异和审查意见，审查意见仍以建议形式保存。
- 页面请求、DSH 领取/进度/结果、用户确认写入持久化协作事件；材料验收清单不再被三秒全量刷新，仅手动刷新或材料操作后更新。

## 验收结果

- `workbench-core`：`npm run check` 通过。
- `workbench-core`：`npm test` 全量通过，包含 25 项端到端测试及新增 ChangeSet 选择性应用测试。
- SQLite-only、归档/永久删除、工作区绑定、双语文献检索、逻辑编辑和 DSH 任务队列改造均保留并通过既有回归测试。

## 当前边界

ChangeSet 当前作为项目版本化载荷投影到 SQLite，功能和迁移行为已满足验收；未来在超大项目场景可进一步拆分为独立表并增加分页查询。

## 2026-09-13：归档入口修正

- 归档、恢复、查看归档和永久删除调整为项目生命周期操作，在 design/write/review 三个阶段均可用。
- 永久删除仍要求归档状态、完整项目名称和二次确认。
- 顶部“归档项目”按钮已存在于新版 Core 页面；若浏览器看不到，需重启 Core 后重新打开页面，避免继续使用旧页面缓存。

## 2026-09-13：新会话阶段恢复修正

- 修复新 DSH 会话重新绑定同一 `assistantKey + projectId` 时被无条件重置为 design 的问题。
- 现在同一助手继续绑定同一项目会继承 design/write/review 阶段；切换到不同项目仍从 design 开始，避免旧项目阶段污染新项目。
- 新增回归测试验证 write 阶段跨 DSH 会话恢复。

## 2026-09-13：文献检索质量与协作链路

- `wb_search_literature` 现在要求 DSH 尽可能先拆解意图，并支持 `englishQuery`、同义词、领域词和年份约束。
- Core 继续执行 OpenAlex/Crossref 双路检索，并新增标题/摘要/作者/来源词项匹配、元数据完整度、年份约束和引用量的相关性评分与重排。
- 检索完成会写入协作事件，DSH 可以读取检索摘要；工作台卡片显示相关性分数和命中词，用户确认后才加入项目书目。
- Core 语法检查及端到端测试 26/26 通过。
